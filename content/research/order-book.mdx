## What is an Order Book?

In a marketplace, some market participants want to **buy**, and others want to **sell**. An order book records resting buy and sell orders, grouped by price.

Below is a **live view** of Binance order-book depth near the current market price. React and TypeScript handle rendering, while a direct WebSocket connection streams the top 20 bid and ask levels in real time.

## Bids and asks

### Bids (Buy Side)
<BestBid />
**Bids** are prices at which traders are willing to buy.

> "Buy 0.5 BTC at 93,000 USDT"

The **best bid** is the highest buy price currently in the book. It defines the top of the bid side.

### Asks (Sell Side)
<BestAsk />
**Asks** are prices at which traders are willing to sell.

> "Sell 0.3 BTC at 93,050 USDT"

The **best ask** is the lowest sell price currently in the book. It defines the top of the ask side.

Together, best bid and best ask define the **top of book**.

## Read the displayed volume and spread

### Order Imbalance
<OrderImbalance />
**Order imbalance** compares visible buy and sell volume. In this demo, it reflects the top 20 levels of the book, not the full market.

Displayed volume does not tell us how many traders placed the orders or whether those orders will remain. Imbalance alone does not predict the next price.

#### Where Does Volume Come From?

Every order in the book has a **size**, how many units someone wants to buy or sell at that price.

For example, Binance might send:

```json
{
  "bids": [["2.35", "1500"], ["2.34", "800"]],
  "asks": [["2.36", "1200"], ["2.37", "600"]]
}
```

The first bid level contains 1,500 units at 2.35 in the quote currency; the first ask level contains 1,200 units at 2.36. Each level can aggregate several orders.

**Total volume** is just adding up all the sizes on each side:

- Bids: 1,500 + 800 = **2,300 total**
- Asks: 1,200 + 600 = **1,800 total**

```typescript
const totalBidVolume = bids.reduce((sum, entry) => sum + entry.size, 0)
const totalAskVolume = asks.reduce((sum, entry) => sum + entry.size, 0)
```

#### How Imbalance Is Calculated

The formula compares how much is on each side:

> **Order Imbalance** = (Bid Volume − Ask Volume) ÷ (Bid Volume + Ask Volume)

Subtract ask volume from bid volume, then divide by their combined volume.

```typescript
const orderImbalance = (totalBidVolume - totalAskVolume) / (totalBidVolume + totalAskVolume)
```

For nonzero combined volume, the result lies between -1 and +1. If both sides are empty, the ratio is undefined.

| Result | What It Means |
|--------|---------------|
| **+1** | Bid volume only |
| **+0.5** | Bid volume is three times ask volume |
| **0** | Equal bid and ask volume |
| **-0.5** | Ask volume is three times bid volume |
| **-1** | Ask volume only |

#### A Simple Example

Using the numbers above (bids = 2,300, asks = 1,800):

$$\frac{2300 - 1800}{2300 + 1800} = \frac{500}{4100} = 0.12$$

Rounded to two decimal places, the imbalance is **+0.12**. In the live card’s percentage format, the unrounded ratio would display as **12.20%**. Bid volume exceeds ask volume in these displayed levels.

### Spread
<Spread />

The **spread** is the gap between the best ask and the best bid:

> Spread = Best Ask − Best Bid

The live value above shows the current spread for the selected trading pair.

A narrow spread puts the best available buying and selling prices close together. A wider spread increases the gap an immediate trade must cross. Liquidity also depends on how much size is available at those prices and farther into the book.

### Market Depth

The colored bars aggregate **volume at each price level**. Longer bars mean more resting size at that price.

Depth shows where displayed size is concentrated and which price levels an immediate order may consume. This partial view cannot account for orders beyond the displayed levels or changes before execution.

## How Trades Execute

A trade occurs when a buy order and a sell order cross.

Two basic order types:

1. **Market order**  
   - “Buy now, whatever the best available price is.”  
   - Matches immediately against the best prices on the opposite side.  
   - Consumes liquidity.

2. **Limit order**  
   - “Buy at 93,000 or better (lower).”  
   - Can execute immediately if it crosses an available price.
   - Any unfilled portion that rests in the book provides liquidity.

When a market buy arrives, it lifts the lowest ask.  
When a market sell arrives, it hits the highest bid.  
Each match removes volume from those levels and the book updates.
