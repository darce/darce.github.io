A coding session ends and the agent loses the thread: which task was active, which review findings are still open, why a decision went one way, and what evidence exists for it. WorkBay keeps that state in the repository so the next session, in any of the supported agent tools, picks it up where the last one left off.

## One journey

`Plan → Task → Work → Review → Findings → Gate → Merge`

A cold session loads its active task and continues it. An independent reviewer records findings that persist, then a gate decides whether the work merges. Claude Code, Codex, Cursor, grok, and VS Code Copilot attach to that same state, though re-entry still takes some friction: each tool surfaces the record differently, and context that was never recorded stays lost.

## Three product decisions

1. **Workflow state, not transcript memory.** The record lives in the project. A new session reloads recorded decisions directly, with no prose recap required.
2. **Independent author and reviewer.** Findings have their own status and commit provenance. Merge authority stays with the parent task.
3. **Vendor-neutral, durable project history.** One manifest keeps commands consistent across tools. If a chosen backend is unavailable, dispatch stops and reports the failure.

## Design Map

The adjacent Design Map ships as the `/ux-map` command, which turns an inventory of jobs, screens, zones, states, actions, flows, and code references into deterministic ASCII, Mermaid, and Markdown artifacts for critique against stable Heuristics Canon rule IDs before implementation. The inventory and critique steps are deterministic; model reasoning happens outside them. The tooling is public. The consumer maps I keep for my own products are private R&D.

## Under the hood

WorkBay stores state in SQLite at `.task-state/handoff.db` and exposes it over MCP. Git hooks guard `main` and branch rules as development safeguards. Bounded `/offload` sends a task to an isolated worktree within a token budget. Optional embeddings add semantic recall over recorded rows.

Installation details and the current schema are in the [WorkBay repository](https://github.com/darce/workbay).
