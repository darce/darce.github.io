## What it is

WorkBay is a SQLite file in the project, two MCP servers, and a set of git hooks. The file holds the active task, its branch and worktree, which slices closed and at which commit, the review findings still open, and the tests that passed.

Agents read and write those rows over MCP (the protocol they use to call tools). The same commands are generated for Claude Code, Codex, Cursor, grok, and VS Code Copilot. A session that ends in one of them can start again in another.

WorkBay stores the task and the gates that still have to pass, not the chat.

## What it solves

A coding agent starts every session cold. Chat summaries fill the gap until you need a finding that is still open, or a decision you already made. The next model can treat a pasted summary as fact. WorkBay records the finding and the commit that backs it.

Skills are advice a model can skip. Hooks installed through `core.hooksPath` still run after you change harnesses: no edits on `main` outside permitted paths, branch names must match the grammar, and the close gate fails while a slice has no recorded decision. Unrestricted shell can still skip hooks.

Creating a worktree, closing a slice, and running the merge gate are make targets. They do not spend a model turn.

A second model can review the branch without reading the first model's transcript. It writes findings into the database. The author has to clear high and medium findings before merge.

## Main features

### Shared commands

Fifteen portable commands come from one manifest. The meaning stays the same; only the install path changes.

| Command | Use when |
| --- | --- |
| `/scope` | The idea is not bounded yet |
| `/tdd` | A slice starts from a failing test |
| `/branch-review` | A branch claims to be done |
| `/offload` | A mechanical slice can go to a cheaper backend under a token cap |
| `/handoff-lifecycle` | You are resuming or switching tasks |

`/plan-analyze`, `/planning-review`, and `/review-parallel` are in the same set. The full list is in the [WorkBay repository](https://github.com/darce/workbay).

A typical task:

```
/scope
/plan-analyze
/planning-review
make task-start
/tdd
/incremental-implementation
/branch-review
make close-check
make task-finish
```

### Hooks

Edits on `main` are refused outside permitted surfaces. Branch names must match `feature/<task-ref>` (plus `maint`, `hotfix`, `release`, `revert`). `make review-ready` fails while findings are open. `make close-check` refuses a finish when any slice lacks a recorded decision. File touches are recorded per slice.

### Database

State lives in `.task-state/handoff.db`. The main tables are active tasks, decisions (with commit SHA), review findings (severity, status, two commit anchors), test results, touched files, blockers, and archives of finished tasks.

`load_session` returns a ranked packet: active task, open findings, recent decisions, touched files. Optional embeddings rank those rows by meaning when a query does not match the original phrasing. They do not replace hooks.

### Author and reviewer

A reviewing agent, usually a different model family, writes findings into the database. The authoring agent sees them on the next `load_session`. Deferred, wontfix, and superseded are allowed exits. Neither agent reads the other transcript.

### Offload

`/offload` sends one self-contained slice to an isolated worktree under a token cap. The lane never merges. You review the diff. Preflight fails before any spend if the backend is missing, the worktree is dirty, or the budget is unset.

Install, upgrade, and the full command list are in the [WorkBay repository](https://github.com/darce/workbay). Restart the agent after install, then start from `/scope`.
