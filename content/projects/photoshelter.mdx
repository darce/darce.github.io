## Keyboard access across the production interface

PhotoShelter’s core menus needed keyboard support. I led the WCAG 2.1 audit and front-end remediation, addressing unlabeled controls and missing ARIA attributes alongside the deeper navigation problems. The accessibility work helped protect institutional contracts associated with $9.2M in annual recurring revenue (ARR) that were at risk if the product could not demonstrate the required accessibility compliance.

![Keyboard navigation for the main menu](/images/photoshelter-keyboard-navigation.gif)

*Keyboard navigation for PhotoShelter’s main menu.*

Polymer and Web Components put interactive elements inside Shadow DOM boundaries. Focus and keyboard events did not move cleanly across those boundaries. I built a custom keyboard layer to bridge them, keeping menu items reachable as people moved between components.

![The main menu goes from mouse to keyboard control](/images/photoshelter-empty-trash.gif)

*Moving from mouse to keyboard control without a mode switch.*

This work covered the behaviour of the interface as well as its markup. I mentored four developers on accessibility patterns and introduced review checklists for new work, so the team could carry those patterns into later changes.

## A workflow prototype that informed Smart Galleries

Working with the Chief Architect, I built exploratory prototypes outside the production path. We could try a workflow and expose its integration problems before committing it to production development.

The workflow-automation prototype informed [Smart Galleries](https://support.photoshelterbrands.com/hc/en-us/articles/10657698741655-Smart-Galleries). An internal estimate put the reduction in later implementation effort at roughly 30%.

## Testing image analysis in the browser

I also built an OpenCV.js prototype to compare image blur in the browser, without backend processing. It tested a lightweight image-analysis workflow in a static-file environment and did not ship as a standalone feature.
