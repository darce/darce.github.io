A blind reader listening to a photograph described as “a person speaking at a lectern” knows what is happening, but may still be missing the point of the picture: who is speaking. If it shows someone the reader knows, a name can make the scene more meaningful.

AltContext combines facial recognition with image description to bring that identity into the text. It matches faces against people the site has confirmed, then uses those identities alongside the image and its page context to draft a description. An editor reviews the result before applying it in WordPress.

<PullQuote>
Knowing who is in the picture can change what the picture means.
</PullQuote>

## Put a name into the scene

Consider a photograph of a familiar speaker at an event. An image model can describe the lectern, the red jacket, and the audience. Facial recognition can connect the speaker to a name in the site's roster. Together, they can produce a description that tells the reader who is speaking and what that person is doing.

That combination is the core of AltContext. The roster supplies the identity; the picture supplies the scene. The post and caption can add relevant context, such as a person's role, where the image supports its use. For a blind reader, the intended benefit is a description that preserves more of the information a sighted reader might recognise immediately.

The editor establishes the roster in WordPress. Groups of faces can be associated with a person, and mistaken groupings can be corrected. Those confirmed identities give the description system a site-specific reference for deciding which names it may use.

A name in the surrounding text is not sufficient on its own. The system checks whether a recognised face supports it before retaining it in the description. Recognition can still be wrong, so a proposed identity remains part of the editor's review.

## Make the description useful on the page

Identity is useful when it helps explain the picture's purpose. A speaker's name may matter in an event report, while a photograph used to demonstrate the cut of a jacket may need different wording. The [W3C image guidance](https://www.w3.org/WAI/tutorials/images/) describes how an image's use and context shape its text alternative.

AltContext draws on information WordPress already holds, including the image caption and the post around it. The model is instructed to check that material against the picture. It should not turn an unrelated sentence from the article into something supposedly visible in the image.

In the review workflow, the editor reads the proposed description and checks the identity, visible details, and relevance to the page. The editor can accept the draft or change its wording before saving it to the WordPress image. Generating a draft and applying it are separate actions in this workflow.

An optional mode saves a longer description alongside the alt text, giving the editor room for detail. The suggested 125-character length for alt text is advisory; [WCAG sets no such limit](https://www.w3.org/TR/WCAG22/#non-text-content). Images that serve only a decorative purpose can be marked accordingly and skip description generation, using the [empty alternative W3C recommends](https://www.w3.org/WAI/tutorials/images/decorative/).

## Alongside PhotoShelter PeopleID

[PhotoShelter PeopleID](https://go.photoshelter.com/brands/blog/facial-recognition-auto-tagging-peopleid/) is a relevant comparison. It matches faces to reference headshots and supplied metadata, helping teams tag and find people in a digital asset library. PhotoShelter also offers [AI-generated alt text](https://go.photoshelter.com/brands/blog/photoshelter-launches-new-ai-generated-alt-text-capability-makes-visual-content-more-accessible/), with options to apply suggestions automatically or review them first.

AltContext focuses this work on the WordPress publishing workflow: using confirmed identities as input to a description of the scene, with blind readers as a primary audience. The site's own roster and editorial context inform the text, and the editor can correct the identity or wording where the image is published.

PhotoShelter's published descriptions do not explain how recognised identities feed into its generated alt text. A direct comparison would need to examine the resulting descriptions and the effort required to correct them. The documented distinction here is AltContext's focus on bringing site-confirmed identities into the WordPress description workflow.

## Keep control of identity data

Facial recognition creates sensitive data about the people in a collection. Control over that data is part of the product design: the site should retain authority over names and editorial decisions, and be able to inspect and remove the recognition data held by the service.

AltContext's recognition and description services run on Oracle Cloud Infrastructure (OCI). Images leave the WordPress host for that processing. WordPress remains the source of record for names and editorial corrections. The hosted service handles recognition and stores the biometric representations used to compare faces.

Database access rules keep each site's recognition records separate. Retention settings let the operator choose how hosted recognition data is kept. Data is retained by default; disposal after synchronisation and on-demand purge are available alternatives. Exports let the operator inspect recognition records, and export and purge operations leave an audit trail. Purging recognition data does not erase the audit records themselves.

The naming controls also let the site withhold a person's name from generated text. A separate connection to an external model provider, built for evaluation, is disabled unless explicitly enabled on the server. These controls explain where processing happens and give the operator concrete ways to manage retained data.

GDPR compliance depends on how the service is operated as well as how it is built. Biometric identification has [additional legal requirements](https://www.edpb.europa.eu/sme/be-compliant/process-personal-data-lawfully_en), including an applicable basis for processing sensitive data. Hosting on OCI does not itself establish compliance: [Oracle shares responsibility with the application operator](https://www.oracle.com/a/ocom/docs/corporate/oci-gdpr-updated.pdf). The controls described here are evidence of the implementation, not a completed legal assessment or a claim of full data sovereignty.

If the service becomes unavailable, new recognition and descriptions must wait. Saved descriptions and locally stored results remain available in WordPress, so existing editorial work does not depend on a live recognition request.

## What the evidence shows

Model comparisons have checked whether descriptions preserve the identities supplied in the context. Some candidates omitted names despite producing fluent sentences; later evaluations showed that smaller models could retain them. An early draft also repeated a caption's background claim about a research residency, prompting clearer rules about what belongs in a description of the image.

These tests examine specific behaviours. They do not establish whether a blind reader receives the right context, or whether an editor reliably catches an incorrect identity. Those questions need evaluation with the people using the descriptions and the review workflow.

Automated checks cover the plugin and service, including accessibility checks on the admin interface. The screens have also been reviewed against a written inventory of their actions and states, using the [process described here](/research/visual-search-workbench-process/).

## Walk through the review yourself

The review step can be tried in a [guided walkthrough inside the demo WordPress site](https://demo.altcontext.com/wp-admin/admin.php?page=alt-context-dashboard#/guided-prototype). It presents one illustrative photograph with its page context, a face the site has matched to a roster entry, and a proposed description. Confirming or rejecting the identity changes the draft; editing, saving, and applying the text remain separate decisions, and an undo restores the previous value.

The walkthrough is a practice copy. It does not run live recognition or description generation, and it does not write to a published page. Refreshing the browser starts a fresh practice. The demo site asks for a sign-in; early-access signup on the [AltContext site](https://altcontext.com) is the way to request one.

The product is in development, before public release.
